# DDL 飞书群提醒

对模型提供 `deadline-reminders` Skill 和 `manage-deadlines` 能力。沿用已有 `list-skills`、`read-skill`，详细说明通过工具结果按需加载。能力通过 `search-capabilities` / `invoke-capability` 使用，不将完整业务工具定义常驻在原生 tools 中。

## 配置群机器人

按[飞书自定义机器人官方文档](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)在目标群添加自定义机器人，在服务用户数据目录的 `.env` 中设置：

```dotenv
SEUDAILY_FEISHU_WEBHOOK=https://open.feishu.cn/open-apis/bot/v2/hook/你的机器人标识
SEUDAILY_FEISHU_SECRET=启用签名校验时填写密钥
```

未开启签名校验时省略 SECRET；如果机器人使用关键词安全规则，可以将关键词配置为 `DDL`。重启服务读取新环境配置。不要把完整 Webhook 或密钥贴进对话。当前服务所有 DDL 使用这一群机器人，变更配置后后续消息发送到新配置的群。

未配置 Webhook 时可以保存任务，工具明确返回“尚不能发送”；不会因为缺少配置提前耗尽重试次数。配置需要在服务端完成，本次没有修改网页或在线更新功能。

## 使用

例如：“帮我记一个实验报告，2026 年 11 月 20 日晚上 23:59 截止，要交 PDF，提前三天、一天、六小时提醒我。”模型读取 Skill 后保存完整时间、要求以及每个节点的提前编写文案，反馈任务 ID 和实际创建的节点。单独的“11.2”需要确认年份和时刻，已过去的日期不自动顺延到明年。

- 默认节点提前 4320、1440、360 分钟，可自定义正整数分钟和各节点的 message。
- 已经过去的节点不创建；全部节点都已过去时，要求调整提醒时间。
- `list` 返回本用户任务、剩余秒数和发送状态；模型可据此展示文字倒计时。
- `update` 根据 ID 替换整个任务和提醒节点；`complete` / `cancel` 停止后续提醒。
- 同一次创建重试沿用 requestKey；不同内容不能复用同一个 key。

工具每次只返回当前用户的任务，配置密钥不进入工具结果。群提醒正文由模型根据用户提供或核实的信息提前写好，触发时不调用模型。

## 持久化、重启和发送边界

任务和发送记录存入用户目录 `.seudaily/deadlines.db`，与源码、版本下载缓存分开。创建任务时保留后端运行状态；启动时发现未完成提醒也保留服务。显式停止服务、关机、休眠或网络不可用期间不能准时通知。

后台每 15 秒检查一次。重启后读取同一数据库，不重新创建任务或重复发送已记录成功的节点。同一任务错过多个节点时只补发最新一条，并注明“补发”和原定时间；截止时间已过的节点标记过期，不继续补发。过期任务可查看、更新或完成。

失败按 2、4、8、16 分钟间隔重试，总计最多 5 次；失败详情和次数可通过 list 查看。恢复 sending 租约、修改/取消检查和数据库领取避免常规重复发送。不过发送成功后响应丢失或进程崩溃仍可能导致重复送达，飞书 Webhook 不提供本功能所需的端到端事务保证。取消也无法撤回已经发出或正在发送的消息。

关停时停止检查并等待当前网络请求结束，再关闭数据库。安装的新内置 Skill 通过目录回退可被旧用户目录发现；同名用户 Skill 优先，不覆盖用户文件。

## 验证

测试覆盖持久化及重启、幂等创建、用户隔离、变更/完成/取消、停机补发、重试与错误脱敏、并发领取，以及真实本地 HTTP 模拟飞书的消息与签名。未使用用户真实群 Webhook 进行发送；配置机器人后需要再确认实际群送达。

本次验证：9 项 DDL 专项测试通过；Node 全套 276 项常规测试和 2 项隔离测试通过，共 278 项；Python 445 项通过；后端/Web 类型检查与后端/CLI 生产构建通过。临时目录启动后端后，健康检查、内置 DDL Skill 发现和正常退出均通过。用户原先未运行的服务保持关闭，未启动实际群提醒。
