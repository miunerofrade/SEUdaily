# 微信接入（文本 demo）

SEUdaily 直接实现[腾讯官方 openclaw-weixin iLink HTTP 协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md)，无需安装 OpenClaw，也无需申请企业微信 webhook。账号是否具备接入资格、手机上的确认和验证码，以微信实际提示为准。当前版本是个人账号的最小文本通信 demo，真实微信账号接入需要本人实测。

## 首次接入

```sh
seudaily WeChat
# 小写 wechat 也可以；使用指定服务时带上相同的数据目录、端口：
seudaily WeChat --data-dir /path/to/data --port 4111
```

命令优先连接同版本、同数据目录、同端口的已有后端。没有后端时启动独立常驻后端；已有临时后端则转为常驻，保留当前任务和连接。终端会展示实际二维码，用微信扫一扫，在手机确认绑定。终端需要足够的行列数容纳二维码和白色留边；不足时界面会提示具体尺寸，扩大窗口或改用网页。

如果微信要求验证码，输入手机上显示的验证码后按 Enter。二维码过期或验证次数过多时按 R 重新扫码（验证码输入期间用 Ctrl+R 刷新）。Esc / Ctrl+C 只退出接入界面，微信收发和后端继续运行。

也可以执行 `seudaily web`，点击左侧底部“微信”。二维码会以浮层展示；从终端开始扫码后，网页也会自动弹出同一个接入请求。手机验证码可以在任一界面输入。关闭浮层不取消接入；“取消接入”停止此次扫码并恢复原先有效的绑定，不删除旧凭证。

非交互终端（输出重定向或管道）中的 `WeChat` 只确保后端常驻并打印状态，不自动发起扫码；随后在交互终端或网页完成接入。

## 验证 demo

绑定后，在微信中给绑定的 Bot 发送一条文本，例如 `你好 SEUdaily`。预期收到：

```text
SEUdaily 微信 demo
会话：wechat-demo
消息：<微信原始消息 ID>
你好 SEUdaily
```

固定内部会话 ID 为 `wechat-demo`，资源 ID 为 `seudaily-wechat-demo`。接收兼容可选 type/state 字段缺省及 NEW/FINISH 用户消息，过滤生成中消息和 Bot 消息。每条消息保存原始微信 message_id（缺失时用 client_id）、发送人、微信 session_id、内部会话和资源 ID。回复携带这条消息的 context_token，to_user_id 指向原发送人；稳定的 client_id 由 Bot、用户、原消息 ID 生成。前端连接窗口展示最近消息和回复状态。

此阶段尚未连接模型、校园工具或现有 Agent 会话；无需模型 API key 就能验证入站、出站和扫码。只接受绑定时扫码者的个人文本，不接受群消息或其他人的消息。图片、语音和文件不下载、不解密、不进入 RAG；收到带有这些内容的消息时，回复当前仅支持文本。后续会话设计和媒体支持另行实现。

## 后续运行与恢复

重复运行 `seudaily WeChat` 会展示既有连接状态，不重复扫码。启动和停止时发送协议生命周期通知，通知失败不阻断服务。正常断网或接口失败时后台指数退避重试；成功后继续接收。凭证失效（协议错误码 -14）会暂停自动请求、保留凭证和待发送消息，需在 TUI 按 R 或网页点击“重新扫码”。微信报告已绑定而本地没有有效凭证时，按界面提示在微信解除旧绑定后重新接入。

退出客户端不会停止服务。手动停止用：

```sh
seudaily stop --data-dir /path/to/data --port 4111
```

再次启动 `serve` 或 `WeChat` 会自动恢复已保存的绑定和消息游标。运行普通 CLI/Web 时，如果数据目录已有微信绑定，也会恢复微信并保持后端常驻；这是启用微信后的服务行为。取消一次扫码不会关闭常驻后端。

自动创建的常驻后端能在退出终端后继续运行，但操作系统重启后需要重新启动；需要开机启动和进程崩溃自动恢复时，使用 [systemd 服务说明](service.md)，仍以 `serve --with-web` 启动。先用同一数据目录完成微信接入，随后 `seudaily stop`，再交给 systemd 启动。不要在 systemd 管理时另开同端口的独立常驻进程。升级前停止服务，更新后重启，保留同一数据目录。

## 本地存储及可靠性边界

数据位于 `--data-dir` 指定目录的 `.seudaily/agent.db`，使用现有 SQLite WAL、FULL 同步和串行事务机制：

- `wechat_account`：单个 Bot 的 token、Bot ID、扫码用户 ID、经过 HTTPS 官方域名验证的 API 地址、接收游标、是否需要重新登录。二维码和手机验证码只在内存中存在，不落盘。
- `wechat_messages`：原始微信 ID、peer、session、固定 threadId/resourceId、文本、回显内容、带路由 context_token 的待发送 payload、pending/sent 状态和接收时间。此表是独立通信 demo 的记录，尚未合并到 Agent 历史消息表。
- 入站消息去重插入与游标提交处于同一事务；游标只有成功响应中的非空新值才会更新。重启先发送待发送回复，再继续长轮询。

文件和目录按私人数据权限保存。Bot token、验证码、context_token 不在状态 API 或界面中返回；不要公开数据库。日志不记录腾讯响应正文或凭证。API 重定向仅接受 `https://*.weixin.qq.com` 的根地址，HTTP 自动重定向被拒绝，避免凭证被转发到其他站点。

网络可能在腾讯已接受回复、客户端尚未记录成功时断开。因此发送采用持久队列和稳定 client_id 重试；不能承诺腾讯服务端一定去重或端到端严格一次投递。如果长期没有网络，旧 context_token 也可能失效，界面会保留等待回复状态和错误提示。

本次不实现媒体存储、RAG、复杂会话路由或定时数据库备份。附件已有存储位置参见 [service.md](service.md)。

## 自动验证与人工测试

自动测试使用模拟 HTTP transport，覆盖腾讯请求头与字段、二维码跳转和手机验证码、凭证过期、游标/消息原子提交、重复消息去重、发送失败重试及重启恢复；不连接真实微信账号。真实账号请重点测试首次扫码、文本回显、退出客户端仍收发、重启服务自动恢复，以及微信端解除绑定后的重新登录。
