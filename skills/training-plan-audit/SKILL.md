# 培养方案与毕业要求

使用 `audit-training-plan` 获取 eHall 个人培养方案、每门课程的学分、各类课程的学分汇总，以及当前和历史课表中的课程。工具只提供事实和证据；根据用户问题自行判断、排序和解释，不要照抄工具结果。

除非用户明确要求同步或刷新 eHall，否则使用缓存数据（`refresh=false`）。调用 Skill 和工具前不要输出“正在激活、读取、检查”等用户可见过程说明，拿到证据后直接用中文回答。

紧凑结果缺少回答所需的已修或未来课程明细时，在同一轮调用 `read-seudaily-task-result`，使用结果给出的 `resultRef` 和 `detailPointers` 精确分页读取。不要使用终端打开 `resultRef`，也不要以“还需要读取”为由提前结束回答。`resultRef`、任务 ID、缓存路径和本地文件路径只供内部使用，不得出现在最终回答中。

## 毕业需要看的规则

- 以个人 eHall 培养方案中的总学分、必修课、限选/任选课、通识/通选、跨学科、英文授课、实践和课程组要求为准。
- 课程组中的 A/B 层级、二选一、四选一等，按课程组要求计算，不把所有备选课都相加。
- 工具结果中的每门课程都有课程名、课程号、课程性质、学分、学期和状态；优先使用工具给出的官方学分汇总。
- 课表出现只表示有修读记录，不能证明通过或已经获得学分，也不能把所有过去学期的方案课自动算作已完成。
- 对课程性质的显式 eHall 字段可以直接陈述；`classificationSource=course_code` 时说明是按课程号识别，`classificationSource=unknown` 时说明仍需确认。

培养方案备注含义不清、规则可能更新或用户要求最新政策时，再用 `search-seu-academic-affairs`；需要全文时使用 `get-seu-academic-affairs-notice`。个人方案与通用规定冲突时明确指出差异，不要用公开帖子覆盖个人方案。

## 公开讨论中常见的问题

公开经验中反复出现两类问题：

- 临近毕业才发现通选/任选学分不够。
- 只看课程名，忽略不同课程的学分值，导致总学分算错。

回答时把“要求学分、已修/在修学分、缺口学分”直接列出来，并把通选课、仅出现在课表中的课程和课程组单独显示。最终毕业判断必须建议核对成绩单、学分认定和教务审核，不得给出无条件的“可以毕业”结论。

详细背景见 [references/research-notes.md](references/research-notes.md)。
