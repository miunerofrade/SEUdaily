# 回归测试

测试以用户可观察的结果和模块接口为依据：请求返回值、文件内容、权限边界、子进程退出和持久化后的状态。

- 优先直接导入模块并调用公开入口。需要隔离网络、数据根目录或后台任务时，在这些依赖边界替换实现；`helpers/module-fixture.mjs` 会编译完整模块，供需要隔离导入的测试使用。
- 不读取源码字符串来断言变量名、导出数量、函数排列；不删除 import、拼接源码或重新暴露私有函数后测试。工具暴露范围通过运行时实际返回的工具集合验证。
- 子进程协议使用真实子进程测试；取消和超时要检查资源确实释放、其他任务继续工作。只有产品约定了响应时限时才使用耗时阈值，CI 机器启动速度不作为功能契约。
- 临时文件放在测试专属目录，通过 `t.after`、`finally` 或 pytest 的 `tmp_path` 清理。恢复测试改动的环境变量，避免写入开发者真实配置。

运行完整回归：

```sh
node scripts/test-node.mjs
.venv/bin/python -m pytest -q
```

Node 测试入口会最后单独执行更新清理测试，避免其进程清理与其他测试的后台服务冲突。
